# Om-LifeOS v1.8.7

Fresh Windows/Tauri source build focused on long-life local storage, bounded rendering and smooth large-data use.

## Architecture
- Native SQLite is the canonical Windows data store.
- The UI does not hydrate the complete history at startup.
- Main history views load bounded pages; subsequent pages use cursor/keyset pagination rather than deep OFFSET scans.
- Saves are incremental: only changed records from the currently loaded window are written.
- Unloaded history is never considered deleted during a page save.
- SQLite WAL, busy timeout and transactional batch writes are enabled.

## Local backup
- SQLite Online Backup API creates a consistent snapshot without replacing the live database file.
- Snapshot is written to a `.partial` file, integrity-checked, then renamed to its final `.sqlite3` name.
- Automatic backup attempts occur only after 90 seconds of user inactivity and when the app is visible.
- Unchanged data does not trigger another automatic snapshot.
- 30 rolling snapshots are retained under `Documents/Om-LifeOS/DatabaseBackups`.

## Import
- `.xlsx` supports Auto / Expenses / Income / Tasks / Notes destination selection.
- `.docx` and text-based `.pdf` import into Notes.
- Legacy `.xls` is rejected explicitly rather than being misclassified as Notes. Save it as `.xlsx` first.

## Build on Windows
```bash
npm install
npm run build
```

The Windows installer is generated by Tauri under `src-tauri/target/release/bundle/nsis/`.
